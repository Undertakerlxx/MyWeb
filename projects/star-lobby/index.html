CASE FILE / 02

ONLINE GAME · 2025

StarLobby

四人联机大厅与副本原型

UnityC#Netcode

PROJECT INTRO

项目介绍

支持四名玩家创建房间、选择角色并进入合作副本的联机原型，覆盖大厅状态同步、断线重连和弱网下的角色移动。

CHALLENGE

大厅和副本之间存在多次场景切换；玩家准备、角色占用和连接状态必须保持一致，同时还要让高延迟玩家获得可接受的移动体验。

OUTCOME

将房间状态与场景对象分离，并加入客户端预测和服务端校正；150ms 模拟延迟下，移动与交互仍保持稳定。

4P联机玩家数
150ms弱网测试延迟
98.6%重连恢复成功率

SYSTEM MAP

项目结构

从核心体验出发，把产品拆成边界清楚、能独立演进的四个部分。

01

会话大厅

维护房间、成员、准备状态与角色选择，保证状态只由服务器权威修改。

02

场景流程

用持久 Session 数据跨越大厅与副本场景，并对加载进度做分阶段确认。

03

移动同步

本地预测即时响应输入，服务端校验并下发快照，客户端对误差进行平滑回滚。

04

断线恢复

以玩家身份令牌重新绑定角色，将关键局内状态从服务器快照恢复到新连接。

BEHIND THE PIXELS

细节设计思路

真正影响体验的，往往是那些看起来很小的决定。

A

大厅状态不依赖场景中的 GameObject

房间数据放在独立会话模型中，UI 只是订阅者。即使切换场景或重建界面，玩家状态也不会丢失。

↳ 数据生命周期长于场景
B

校正应该发生，但不必被玩家看见

小误差用插值逐步收敛，只有超过阈值才瞬移纠正；镜头跟随使用独立平滑层隔离网络抖动。

↳ 预测、校验、表现三层分离
C

把弱网当成正常状态设计

操作未确认时显示轻量状态，失败后回滚局部交互并保留玩家选择，而不是把用户直接踢回首页。

↳ 失败可恢复
