群体导航与弹幕系统

大规模群体跟随、避障与对象池弹幕

C#UnityECS

PROJECT INTRO

项目介绍

基于 Unity DOTS/ECS 的大规模群体跟随与弹幕系统。场景中批量生成代理单位，它们围绕主角保持指定距离，通过共享 Flow Field 获取全局移动方向，并结合 KNN 快速邻居查询与 ORCA 局部避障，实现群体单位的自然分流与实时避碰。ECS 对象池驱动的弹幕系统实现代理可批量发射投射物，投射物生命周期结束后回收到池中复用，减少高频创建和销毁带来的性能开销。整个场景通过 ECS 数据导向设计和 Job 化计算，支持大量单位同时移动、避障与弹幕射击。

KEY CONCEPTS

项目知识点

基于 ECS 架构文档，围绕数据导向设计、并行计算与系统调度梳理核心实现。

01

ECS 数据导向设计

Entity 仅标识对象，Component 使用结构体保存状态，System 批量处理同类组件；SoA 连续内存布局更利于缓存命中与大规模实体遍历。

02

Authoring 与 Baker

在 Inspector 通过 Authoring 提供配置入口，再由 Baker 烘焙为 ECS 组件和动态缓冲区，让运行时数据适合系统与 Job 高效读取。

03

共享流场与 ECS 单例

FlowFieldSystem 从唯一 Grid Entity 读取配置与缓冲区，只构建一次全局流场；所有 Agent 共享方向结果，避免重复寻路计算。

04

Burst 与 IJobEntity 并行

将流场方向、积分场等数据以 NativeArray 只读传入 Job，通过 BurstCompile 与 ScheduleParallel 并行计算大量 Agent 的期望速度。

05

查询缓存与动态缓冲区

EntityQuery 确定处理对象集合，ComponentLookup 按 Entity 随机读取固定组件，BufferLookup 管理每个 Agent 长度可变的邻居列表。

06

EntityCommandBuffer

批量生成 Agent 与投射物时延迟执行结构性变更，统一 Playback 后再创建实体和添加组件，避免查询或 Job 引用在处理中失效。

07

流场重建请求实体

障碍、净空或目标格变化只创建并合并 Request Entity，再由 FlowFieldSystem 集中消费，清晰分离生产者、消费者与请求生命周期。

08

系统执行顺序

先更新障碍和 Clearance，再构建流场、计算转向、收集邻居、执行 ORCA 避障，最后移动实体；通过更新组和依赖保证数据顺序正确。
