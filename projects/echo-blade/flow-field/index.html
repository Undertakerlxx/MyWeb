FLOW FIELD / CORE PIPELINE

流场寻路基础

INTEGRATION · DIRECTION · STEERING

适用于大量单位向同一目标或同一目标区域移动。流场预先为整张地图构建一份共享方向数据，使每个单位只需读取当前位置的方向并持续移动。

CORE DATA

安全地图、积分场与方向场

流场寻路由三类数据组成：安全地图负责判断单位能否通过；积分场记录各网格到目标的累计代价；方向场为每个网格保存推荐移动方向。

安全地图标记可通行区域，并在判断时考虑单位体积。
积分场保存各网格到目标的累计代价，为方向场提供“下坡”依据。
方向场保存每个网格的推荐移动方向，单位每帧读取当前位置。

基本移动逻辑

  1. 构建积分场遍历地图网格，计算每个网格到目标网格的累计代价。
  2. 生成方向场再次遍历网格，检查周围八邻域，指向累计代价最小的可通行邻居。
  3. 持续顺流移动每个单位根据所在网格的方向场数据持续移动，形成沿流场前进的效果。
BUILD PHASES

流场构建的四个核心阶段

01 / 安全地图结合障碍物与单位尺寸，输出可通行性信息。
02 / 终点集合为每个安全连通区域选择可到达的驻留环种子格。
03 / 积分场从所有种子同时 BFS，填充 Distance = 0、1、2……。
04 / 方向场为每个网格选择积分值更小的合法邻居，输出方向向量。

RUNTIME / DESIGN DETAILS

关键实现设计

STAY · CLEARANCE · SMOOTH · SWEEP

共享方向解决“往哪里走”，但停驻距离、角色尺寸、移动平滑和碰撞安全，需要在读取流场之后继续处理。

驻留环种子格

远程敌人应保持合适射击距离，而不是贴近主角。可将目标周围近似圆环上的网格定义为驻留环种子格。种子被占满时，回退到更外侧、距驻留环更远的可用网格；每个安全连通区域都应尝试寻找种子，避免不可达区域产生无效方向。

Clearance 构建

仅依赖网格中心点无法保证 3D 单位移动安全。角色具有半径和高度，即使网格标记为可通过，胶囊体仍可能擦墙、卡角或嵌入碰撞体。例如宽度 0.8 m 的窄缝无法容纳直径 1.0 m 的单位，应在安全地图阶段提前过滤。

双线性插值

单位不会始终精准踩在网格中心。依据当前位置邻近四格的方向向量，并按到各网格中心的距离分配权重，可合成更平滑的方向，减少边界处的方向突变，让轨迹和朝向旋转都更自然。

胶囊体扫掠与滑墙

使用 Collider Cast 将单位实际碰撞形状沿移动向量扫过整段路径，寻找首次接触点。这能处理贴墙穿模、高速位移隧穿和斜角穿障；碰墙后移除朝墙内的分量，保留沿墙面分量，实现连续的滑墙移动。

PERFORMANCE / COMPARISON

并行构建与 A* 对比

PARALLEL BUILD · SHARED RESULT
PARALLEL DESIGN

只读共享数据，按格并行写入

流场构建中存在大量互不冲突的网格计算，适合使用 IJobParallelFor 并行处理。

环节并行方式安全性说明
重构前清空旧流场数据IJobParallelFor各线程只写入不同网格索引，不读取邻居数据。
积分场后的方向场构建IJobParallelFor各线程共享只读积分场，但仅写入各自负责的方向格。

并行前提避免多个线程写入同一个网格；只读共享数据可以安全地被多个线程同时访问。

A* VS FLOW FIELD

适合大量单位追逐同一目标

对比项A* 寻路流场寻路
计算单位每个单位各算一次同一目标的所有单位共享一次计算
输入一个起点 + 一个终点一个目标或目标区域
输出一条完整路径点列表全地图每格的积分值和方向
单位移动沿路径点逐个前进每帧读取当前位置方向，持续顺流移动
适合场景目的地不同、需要精确路径大量单位追同一目标、向同一区域集合
群体规模单位越多，重复计算越多目标不变时，单位增加主要只增加读场成本
地图变化通常只重算受影响单位的路径通常重建整张流场
路径个性化强，每个单位可有不同目标或代价弱，共享全局方向，个体差异交给局部避障
内存形式每个单位存一条路径点缓冲区网格存一份积分场和方向场

结论当大量单位共享目标时，流场将路径计算从“每个单位重复求解”转为“一次构建、多单位读取”。配合 Clearance、双线性插值、胶囊体扫掠与局部避障，可在保持群体移动效率的同时，获得更自然、更稳定的实际运动效果。
